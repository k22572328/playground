# playground

多人連線的遊戲平台，Go 後端 + 網頁前端。登入、大廳、開房、斷線重連都是共用的，
遊戲本身是插進來的模組 —— 目前收錄**台灣規則的四人大老二**。

## 快速開始

```bash
GO111MODULE=on go run ./cmd/server
```

然後用瀏覽器開 <http://localhost:8080>。每個人各開一個分頁（或各自用自己的裝置連到同一台機器）
就能玩 —— 大老二要湊滿四個人。

前端已經用 `go:embed` 編進執行檔，所以**在任何目錄下執行都能正常開啟**，
部署時也只要搬一個執行檔。

參數：

```bash
go run ./cmd/server -addr :3000        # 換個埠
go run ./cmd/server -web web           # 改讀外部前端目錄（開發用）
```

- `-addr`：監聽位址，預設 `:8080`
- `-web`：前端靜態檔目錄。留空（預設）用編進執行檔的版本；
  指定目錄則改讀外部檔案，改了前端不必重新編譯。
  指定的目錄若不存在會直接報錯，不會默默跑出一台每頁 404 的伺服器。
- `-logdir`：牌局紀錄的存放目錄，預設 `logs`。設為空字串則不記錄。

## 牌局紀錄

每開一局就會在 `logs/` 底下產生一份紀錄檔（例如 `2026-09-17_140708_AAB.log`），
內容足以重現整局，方便事後追查問題：

```
--- 初始手牌 ---
座位0 房長：3♣ 3♥ 4♥ 6♠ 8♣ 8♦ 8♥ 10♥ J♦ Q♥ K♣ K♦ 2♦
...
座位0 房長 持有 ♣3，由他開局

--- 第 1 個 Round ---
[   0.01s] 第 1手  座位0 房長 出 單張：3♣
[   0.01s] 第 2手  座位1 客人1 出 單張：4♣
...
[   1.39s] 第58手  座位3 客人3 出 單張：A♠
[   1.39s]        >>> 座位3 客人3 手牌出完，取得第 1 名 <<<
[   1.39s]        --- 第 5 個 Round 結束，座位3 客人3 贏下檯面 ---
[   1.39s]        座位3 客人3 已離場，首攻權由順位交給 座位0 房長

=== 本局結束（共 63 手，歷時 1s）===
第 1 名：座位3 客人3
第 4 名：座位2 客人2（手牌未出完）
```

記錄的是成功的動作（發牌、出牌、PASS、Round 邊界、名次），
被規則擋下的嘗試不會寫進去。寫檔失敗只會讓紀錄中斷，不影響遊戲進行。

## 玩法流程

1. 開啟網頁，輸入暱稱
2. 在大廳選好遊戲、建立房間，或加入別人的房間
3. 房長可以踢人；人數到齊後房長按「開始遊戲」
4. 以下是大老二：點選手牌再按「出牌」，壓不過就按 PASS
5. 依序決定第 1～4 名

## 程式架構

最重要的一條界線是**平台與遊戲**。平台負責所有遊戲都一樣的事 ——
連線、登入、大廳、開房、座位、斷線重連 —— 它**完全不知道房間裡在玩什麼**：

```
internal/platform        大廳、房間、WebSocket、session、資料視圖
  └ game.go              平台與遊戲的界線：Kind 與 Instance 兩個介面
internal/games/bigtwo    把大老二接上介面：解析動作、整理畫面資料
  ├ rules                純規則：牌、牌型判斷、比大小。無狀態、無 I/O
  ├ match                一局的流程：Round、PASS 資格、名次、順位
  └ gamelog              把一局牌寫成人看得懂的紀錄檔
internal/shuffle         洗牌器，平台與遊戲共用
web/                     前端靜態檔（原生 HTML/CSS/JS，無建置步驟）
  ├ app.js               平台前端：登入、大廳、房間
  └ games/bigtwo/        該遊戲的牌桌畫面
cmd/server/              進入點，把遊戲註冊進平台
```

`platform` 不 import 任何遊戲套件（那會造成循環依賴），
而是由 `cmd/server` 呼叫 `platform.Register(bigtwo.Kind())` 組裝起來。

這樣分層的用意：**規則可以完全離線測試**，不需要起伺服器、不需要瀏覽器。
`rules` 與 `match` 兩層加起來涵蓋了所有遊戲規則，改規則只會動到這兩層。

### 資料流

```
瀏覽器 --WebSocket--> platform --Act--> bigtwo --> match --> rules
                         ^                                    |
                         +---- ViewFor 產生各玩家專屬的視圖 <---+
```

平台只透過三個方法操作遊戲：`Act`（做一個動作）、`ViewFor`（產生某座位看得到的畫面）、
`Over`（這局結束了嗎）。動作與畫面的內容都是各遊戲自己定義的 JSON，平台不解讀。

每位玩家收到的狀態都是為他量身產生的：**你只看得到自己的手牌**，
其他人一律只揭露張數。這由各遊戲的 `ViewFor` 負責，大老二的實作在
`internal/games/bigtwo/view.go`。

## 加一個新遊戲

平台不必改。照這四步：

1. 在 `internal/games/<id>/` 實作 `platform.Instance`（`Act` / `ViewFor` / `Over`），
   並提供一個回傳 `platform.Kind` 的函式，填 ID、顯示名稱與人數範圍。
2. 在 `cmd/server/main.go` 的 `init()` 裡 `platform.Register(...)`。
3. 寫 `web/games/<id>/table.js`，用
   `Playground.registerGame(id, { screen, mount, render, unmount })` 掛進前端。
4. 在 `web/index.html` 加上該遊戲的畫面區塊與 `<script>`。

前端靠 ID 決定要載入哪個畫面，所以兩邊的 id 字串必須一致。
人數範圍由 `MinSeats` / `MaxSeats` 決定，大廳的選單會自動跟著顯示。

## 規則實作重點

規則細節與一般認知略有出入的地方，都寫在對應的程式註解裡：

- **合法牌型只有六種**：單張、對子、順子、葫蘆、鐵支、同花順。
  三條與普通同花都**不能**單獨出牌。
- **普通牌型不能跨牌型互壓**：葫蘆壓不過順子，兩者沒有大小關係。
  同一個 Round 只能用相同牌型對抗。
- **鐵支與同花順是特殊牌型**：可以無條件壓過任何普通牌型，不限張數。
  強度為「普通牌型 < 鐵支 < 同花順」，最小的同花順也大於最大的鐵支。
- **順子順位不是單純比大小**：`A2345 < 34567 < … < 10JQKA < 23456`。
  `A2345` 最小、`23456` 最大，而 `JQKA2` 不成立。
  `23456` 用其中的 **2** 當比較牌，不是 6。
- **PASS 會失去整個 Round 的出牌資格**：即使檯面之後被鐵支炸掉、牌型改變，
  已 PASS 的人也不能再回來出牌。下一個 Round 才恢復。
- **順位**：贏下 Round 的人若已經打完手牌離場，由他的下一個
  仍有手牌的座位接手首攻。
- **打完最後一手就立刻結束 Round**：名次在出完牌的當下就確定，
  而且因為出完的人已離場，沒有人需要再壓他的牌，檯面立刻清空，
  順位者馬上取得自由出牌權，不必讓其他人再空跑一輪 PASS。
- **第四名不用打完**：第三名產生時整局立刻結束。
- **座位每局重洗**：開局時重新安排座位，不照進房順序，
  所以房長不會因為先進房就固定坐在某個位置。

## 洗牌與公平性

發牌與座位順序都用 `crypto/rand` 洗，不是以時間當種子的 `math/rand` ——
後者只要知道伺服器的啟動時間就能推算出之後每一局的牌。

洗牌用 Fisher–Yates，並以拒絕取樣避免模數偏差。這些都有測試把關：
24 萬次取樣的卡方檢定、每張牌落到每個位置的分布、以及 2 萬局實際發牌中
每張牌落到每個座位的比例。

## 測試

```bash
go test ./...              # 完整測試（含十萬局隨機對局，約 2~4 分鐘）
go test -short ./...       # 快速版（兩千局），日常開發用
go test -race ./...        # 併發檢查，改動 server 或 lobby 後務必跑
```

測試涵蓋範圍：

| 層 | 內容 |
|---|---|
| `rules` | 牌型判斷、比大小；窮舉全部 2,598,960 種五張組合驗證分類正確；大小關係的反對稱性與遞移性 |
| `match` | Round 流程、PASS 資格、名次與順位的臨界情況；十萬局隨機對局驗證流程永不卡死 |
| `bigtwo` | 動作解析與視圖：只揭露該座位看得到的資訊、畸形動作 JSON |
| `platform` | 房間生命週期、連線協定、畸形輸入、斷線重連；四人完整對局的端對端測試；大量並行加入／開始／進出的壓力測試 |
| `shuffle` | 洗牌的均勻性（卡方檢定）、併發安全，以及與有偏差做法的對照 |

幾個值得知道的測試設計：

- **窮舉驗證**：`TestEveryFiveCardHandClassifies` 把整副牌所有五張組合跑過一遍，
  並與理論數量比對（同花順 40、鐵支 624、葫蘆 3744、順子 10200）。
  漏判或誤判都會立刻現形。
- **性質測試**：`TestBeatsIsAntisymmetric` 與 `TestBeatsIsTransitive`
  驗證大小關係不自相矛盾 —— 這是比逐條測試更強的保證。
- **隨機對局**：`TestRandomMatchesAlwaysFinish` 跑十萬局，確認流程不會卡死、
  不會輪到已離場的玩家、名次一定排得出來。
- **`-race` 是必要的**：開發過程中曾靠它抓到兩個一般測試完全測不到的錯誤
  （對已關閉的 channel 送資料、未上鎖讀取房間狀態）。

## 斷線重連

連線建立時伺服器會發一組 token，前端存進 `localStorage`，
重新整理或短暫斷線後帶回來就能接回原本的身分：

- **遊戲進行中斷線**：座位保留 60 秒，期間牌局暫停，其他人會看到
  「等待 XXX 重新連線…」。回來後座位與手牌原封不動；超過 60 秒才移出房間。
- **還沒開局就斷線**：直接離開房間（留著只會擋住別人加入），
  但暱稱仍保留，重連後不必重新輸入。
- **保護先連上的人**：若原本的連線還活著，別人拿著同一組 token
  無法把身分搶走 —— 會被擋下並提示「這個身分已經在別的視窗使用中」。

token 用 `crypto/rand` 產生：猜中別人的 token 等於能接管他的座位與手牌。

## 已知限制

- 房間資料只存在記憶體，伺服器重啟就消失。
- 沒有電腦玩家，一定要湊滿真人（大老二是四個）。
- 目前只有一種遊戲。平台的介面已經備好，但第二種遊戲還沒寫。

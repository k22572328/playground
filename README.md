# 大老二

台灣規則的四人大老二，Go 後端 + 網頁前端，多人連線對戰。

## 快速開始

```bash
GO111MODULE=on go run ./cmd/server
```

然後用瀏覽器開 <http://localhost:8080>。四個人各開一個分頁（或各自用自己的裝置連到同一台機器）就能玩。

參數：

```bash
go run ./cmd/server -addr :8080 -web web
```

- `-addr`：監聽位址，預設 `:8080`
- `-web`：前端靜態檔目錄，預設 `web`

## 玩法流程

1. 開啟網頁，輸入暱稱
2. 在大廳建立房間，或加入別人的房間
3. 房長可以踢人；滿四人後房長按「開始遊戲」
4. 點選手牌再按「出牌」，壓不過就按 PASS
5. 依序決定第 1～4 名

## 程式架構

分層由內而外，依賴單向往外層流動 —— 內層完全不知道外層的存在：

```
internal/game    純規則：牌、牌型判斷、比大小。無狀態、無 I/O
internal/match   一局的流程：Round、PASS 資格、名次、順位
internal/lobby   房間管理：建立、加入、踢人、開始
internal/server  WebSocket 與 HTTP，以及送給前端的資料形狀
web/             前端靜態檔（原生 HTML/CSS/JS，無建置步驟）
cmd/server/      進入點，只負責組裝
```

這樣分層的用意：**規則可以完全離線測試**，不需要起伺服器、不需要瀏覽器。
`internal/game` 與 `internal/match` 兩層加起來涵蓋了所有遊戲規則，
改規則只會動到這兩層。

### 資料流

```
瀏覽器 --WebSocket--> server --> lobby --> match --> game
                         ^                            |
                         +---- 推播各玩家專屬的視圖 <---+
```

每位玩家收到的狀態都是為他量身產生的：**你只看得到自己的手牌**，
其他人一律只揭露張數。這在 `internal/server/view.go` 處理。

## 規則實作重點

規則細節與一般認知略有出入的地方，都寫在對應的程式註解裡：

- **合法牌型只有六種**：單張、對子、順子、葫蘆、鐵支、同花順。
  三條與普通同花都**不能**單獨出牌。
- **普通牌型不能跨牌型互壓**：葫蘆壓不過順子，兩者沒有大小關係。
  同一個 Round 只能用相同牌型對抗。
- **鐵支與同花順是特殊牌型**：可以無條件壓過任何普通牌型，不限張數。
  強度為「普通牌型 < 鐵支 < 同花順」，最小的同花順也大於最大的鐵支。
- **順子順位不是單純比大小**：`A2345 < 34567 < … < 10JQKA < 23456`。
  `A2345` 最小、`23456` 最大，而 `JQKA2` 不成立。
  `23456` 用其中的 **2** 當比較牌，不是 6。
- **PASS 會失去整個 Round 的出牌資格**：即使檯面之後被鐵支炸掉、牌型改變，
  已 PASS 的人也不能再回來出牌。下一個 Round 才恢復。
- **順位**：贏下 Round 的人若已經打完手牌離場，由他的下一個
  仍有手牌的座位接手首攻。
- **第四名不用打完**：第三名產生時整局立刻結束。

## 測試

```bash
go test ./...              # 完整測試（含十萬局隨機對局，約 2~4 分鐘）
go test -short ./...       # 快速版（兩千局），日常開發用
go test -race ./...        # 併發檢查，改動 server 或 lobby 後務必跑
```

測試涵蓋範圍：

| 層 | 內容 |
|---|---|
| `game` | 牌型判斷、比大小；窮舉全部 2,598,960 種五張組合驗證分類正確；大小關係的反對稱性與遞移性 |
| `match` | Round 流程、PASS 資格、名次與順位的臨界情況；十萬局隨機對局驗證流程永不卡死 |
| `lobby` | 房間生命週期；大量並行加入／開始／進出的壓力測試 |
| `server` | 連線協定、畸形輸入、斷線處理；四人完整對局的端對端測試 |

幾個值得知道的測試設計：

- **窮舉驗證**：`TestEveryFiveCardHandClassifies` 把整副牌所有五張組合跑過一遍，
  並與理論數量比對（同花順 40、鐵支 624、葫蘆 3744、順子 10200）。
  漏判或誤判都會立刻現形。
- **性質測試**：`TestBeatsIsAntisymmetric` 與 `TestBeatsIsTransitive`
  驗證大小關係不自相矛盾 —— 這是比逐條測試更強的保證。
- **隨機對局**：`TestRandomMatchesAlwaysFinish` 跑十萬局，確認流程不會卡死、
  不會輪到已離場的玩家、名次一定排得出來。
- **`-race` 是必要的**：開發過程中曾靠它抓到兩個一般測試完全測不到的錯誤
  （對已關閉的 channel 送資料、未上鎖讀取房間狀態）。

## 已知限制

- 房間資料只存在記憶體，伺服器重啟就消失。
- 斷線重連會回到大廳，不會自動接回進行中的牌局。
- 沒有電腦玩家，一定要湊滿四個真人。
